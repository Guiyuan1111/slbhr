# 路线产线手册（内核初排 → MC 鲁棒门 → 真服务端门禁）

> 定稿：2026-10-11。来源：批 1 产线实战（forest_06/06_1/12 通关 + 06_1 三次门禁失败的根因取证）。
> 适用：批次 1-5 全部 47 关的路线生产。批次划分见 [level-batches.md](level-batches.md)。
> 配套工具：`scripts/e2e/routetool/kernel.mjs`（确定性内核）、`scripts/e2e/mc.mjs`（MC 鲁棒门）、
> `scripts/e2e/route.mjs`（真服务端门禁，`--offset-b` 可对 B 页做毫秒补偿）。

## 0. 产线流水线（每关固定五步）

1. **侦察**：`parseLevel` 打印 spawn/doors/机关/地形网格（`A.ground[r*cols+c]`、
   `A.groundType` 名 `["so","/","\\","C","D","water","lava"]`）；液池/墙/竖井定位。
2. **内核初排**：`runKernel(level, route, {traceTo: []})` 逐帧 trace 排线，达到
   `{won:true}`。trace 坐标是**角色中心**，脚底≈y+35。
3. **MC 鲁棒门**：`node --import tsx scripts/e2e/mc.mjs --level <L> --trials 150`，
   **≥98% 才准进真服务端**（<98% 回第 2 步按 §2 铁律重构，禁止拿脆弱路线去撞门禁）。
4. **真服务端门禁**：`route.mjs --level <L> --repeat 3`，ALL PASS（B 页系统性迟到时加
   `--offset-b -25`）。
5. **提交**：路线 JSON 单独 commit（无 co-author），source 字段写明分段结构。

## 1. 服务端时序噪声模型（2026-10-11 forest_06_1 三轮门禁实测）

- 常规抖动：每事件 done-t ∈ [1,5]ms（315 事件样本），OFFSET=-10 的 10ms 吸收余量内
  **不翻帧**。
- **离群**：~1/315 事件 40ms（≈+2.4f 迟到）——单发即可毁掉相位敏感段（实例：打在
  池-1 跳的 R 松开键，残留 +9px 使下游连锁 tap 钉死雪崩，整关 1/3 败）。
- 推论：**任何"事件间相位耦合链"都是必炸结构**；鲁棒性只能来自空间锚点。

## 2. 结构铁律（按自愈能力选原语，自上而下优先）

| 原语 | 自愈机制 | 用法 |
|---|---|---|
| **长按进墙** | 墙钉吸收一切到达时差 | 朝墙/朝门长按方向直到被钉住再松开；"早到/晚到"都终结在同一位置 |
| **定点跳** | 每跳只依赖局部几何 | 钉在台阶脸时按住方向+点跳 up（4-6f），落地稳 12-16f 再跳下一级 |
| **坠落井+墙底** | 竖井坠落被底墙接住 | 长按方向穿过竖井，落到井底墙钉位 |
| **对称镜像** | 双方路线互为镜像时误差同构抵消 | forest_12 MC 100% 的根因 |
| 连锁 tap 相位链 | ❌ 无 | **禁止**：每 tap 落点喂下一 tap 相位，±2f 离群即雪崩（MC 78%） |
| 惯性滑停 | ❌ 无 | **禁止用于门带停靠**：落点散布 ±50px 会跨出门带（forest_03 fb 336/430 失败位） |
| 零冗余风柱窗口 | ❌ 无 | **禁止**：窗口宽度必须 ≥±3f（早进晚出逐柱内核验证） |

门带停靠正解：**长按方向走入门口直到底墙钉住**（门 Rect 64px 宽，body 重叠即开门，
驻留 ~51f；钉位天然在带内），而非计时松键滑停。

## 3. MC 判据与抖动模型

`mc.mjs` 滑步模型：每事件 P(+1f)=2%、P(+2f)=0.6%、P(+3f)=0.2%（保守覆盖 40ms 离群），
同帧 up 先于 down。判据 ≥150 轮 ≥98% ≈ 真门禁 3/3 概率 ≥94%。归因技巧：
**按角色分离抖动**（只抖 fb / 只抖 wg 各 100 轮）可把碎片化段定位到单一角色，
再内核 trace 对比失败终点（如 fbEnd=(976,541)=风柱链断 / (336,541)=门带欠停）。

## 4. 物理速查（内核实测常量）

- 空中按住 L/R：vx 渐近 4.5px/f（按住不衰减）；松开 τ≈4.3f 指数衰减。
- 地面行走加速 0.18/f²；摩擦 ×0.8/f。
- 跳：上升 124px/27f；仅 grounded 的 up 按下沿触发。
- 液体：上方进入可站 surface（齐平慢走安全）；侧向被杯壁挡；下沉过面即死。
  **fb 遇水死/岩浆免疫；wg 遇岩浆死/水免疫**（换液变体里"对己致命池变安全池"
  是路线差异的主因）。
- 门：Rect(x,y,64,64)；重叠开 25fps 动画，双门 isUp（frac≥21）才 win；驻留 ~51f。
- 风：initialState 恒定不接组信号（level-batches.md §1.2）；内核确定性。

## 5. 并行产线规约（子 agent）

- 每关独立 `TEMP/<agent名>/` 工作区，结束自查清理；**禁止** agent 做 git commit /
  起服务端 / 改 scripts|packages（交付物只有路线 JSON + 报告）。
- agent 提示词 = §0 流水线 + §1-4 铁律 + 该关侦察情报（死亡点/失败终点/门位）。
- 并发上限 ~4：同时 5 个会触发模型限流（"Model request failed"，隔数分钟重试即可）。
- 交付验收 = 内核 win + mc.mjs ≥98%；门禁由中央串行执行（并行门禁会互相加压抖动）。
