## 坐标变换（活体实证基准）

- 屏幕坐标 = **(−32·b2x, −32·b2y)**（镜像+缩放，无偏移）。`ground-live-screenspace.json` 存的是 RAW b2 坐标（负值），必须先变换再使用。

## 关键几何（西画廊摆渡区）

- 640 拉杆房地板：x0-544（poly #36）；东出口台阶（楔 #35 #30）下到 704 大厅
- **480 台面** poly #51：x160-640，y480-512（顶面 480 与 P1 UP 平齐；底面 512 = 走廊天花板 → 走廊内跳跃脚上限 568）
- 台面东楔 #50（x640-672，480→512）衔接 512 画廊
- **竖井 x32-160 上方完全开放**（无顶）——井内跳跃可达满弹道
- P1 定义 (32,480,128,32)：UP 顶面 480 / DOWN 顶面 576；DOWN 位只留 32px 地面净空（玩家无法在地板上从其西侧走过）；东角 x160 会"接住"下降的玩家（X 相位卡住 → 滑落到地板）

## 拉杆接触翻转模型（与旧认知的决定性差异）

- 任何穿越拉杆柱区（x299-309, y608-672）都翻转；冷却 0.6s 吞掉重复触发；冷却到期时**若仍有玩家站在柱区会再翻转**（电平触发）
- 旧"跑过不翻转"假设不存在 → 原双乘渡船方案不可行

## 下沉平台 = 踏板（最终方案）

1. 穿柱一次翻转 → P1 降到位（576）
2. 从 640 地板跃上静态 P1（跨东角时脚 568-571 高于台面 576 ✓），贴西墙站定
3. 井内东行 x110 → 竖直跳 + 0.3s 后东漂 → 跃上 480 台面（落点 x170-254）
4. W 额外做两次空翻复位（UP 空+DOWN 装载自己），中间 pause ≥0.85s（冷却 0.6s）
- 浏览器实测教训：**起跳点右缘必须 ≤x134**（x160 西壁 + 512 底面会把跳跃封顶在 feet 568，永远跳不上）

## P0 接力（右升降台）

- 板 b1 (320,448,64,64) 在 480 台面；板 b2 (960,352)；P0 def (1088,384,128,32)：UP 384 / DOWN 480
- DOWN 位底面贴 512 地板 → 32px 自动上台阶可直接走上去
- **玩家禁止站在下行路径（x1088-1216）下**：内核对 vy=0 玩家 vs 下降平台无挤开解算（会永久嵌入）

## 352 板与推箱

- 板 poly #62：x0-1088 y352-384；箱起 (704,224) → 推到 x192 顶西塔东面（塔 x0-192 顶 224，高出箱顶 64px → 需 vjump 后=0.17s 提前上升）
- 支柱顶 800 仅 x1152-1248 平坦；西壁 64px 必须跳；顶→大厅跳跃处天花板 608（x1120-1248）

## 内核实修（本轮双 fix）

- **平台端点落位吸附**（c79b0c9）：16px/s 步进浮点残差曾达 0.27px，被 0.5px 死区冻结 → 玩家 32px 自动上台阶 lift 判定永久差临界。修法：`mv >= dist || dist - mv <= 0.5` 时直接落位
- 原版顶部藤蔓时钟实拍为**正计时**（00:00 起已用时间 MM:SS）；早先"2:00 倒计时"实证有误，已改正（a26308c）

## 浏览器 bot 实测要点（TEMP/browser-bot.mjs）

- 客户端暴露 `globalThis.__fwInit.net.room.state`（players 以 "fireboy"/"watergirl" 为键；补丁 50ms）→ grounded 由 anim≠jump/fall 推导
- 状态滞后 ≤50ms → 行走指令天然过冲 ≤18px；跳跃指令须带兜底重试（jumpDir near+retry；vjump 漂移限时 0.45s 防走出平台）
- 菜单流：#password → #btn-create → #hud-room 取房间码 → 页二 #btn-join
- 输入即真实键盘事件（F 用方向键、W 用 WASD，KeyboardInput 变化才上报）

## IDM 接管问题的结构性绕行

- IDM 按进程/网卡层嗅探 URL 扩展名（.mp3 等），`--disable-extensions` 无效
- 复刻侧根治：音频走 `/assets/audio/s/:name`（服务器补 .mp3、octet-stream），URL 无媒体扩展名即不在接管名单
- 只读原版（8099）采集时：本地改写代理 + `page.route(正则含 ?v= 查询串)` abort——请求不出浏览器、零 socket、零媒体字节，IDM 无物可劫

## 路线产线与 v35（2026-10-11，M1 工具化）

> 本节起路线不再以 TEMP 脚本内的 JS 表为准，改由产线工具维护**平坦事件 JSON**：
> `scripts/e2e/inputs/routes/forest_01.json`（fb/wg 各一条 `[{f, dir, type}]`，56+55 事件）。

**v35 路线**（86de12a）：由优化器对 v34 做坐标下降硬化产出——逐事件 ±1f 扫描致命数 35/111 → 8/111
（残余 8 处为杠杆混沌区单角色邻域无可行移动的确定性死锁，详见下节根因）。内核复核 WIN @f2365。

**产线工具**（1224b8e，`scripts/e2e/routetool/`）：
- `kernel.mjs`：内核 harness——tsx 直载 TS 内核（与真实服务端同一份实现），双关卡库解析
  （data/tutorials/levels + data/forest/levels）；`runKernel` 回跑路线返回 WIN/死亡帧。
- `validate.mjs`：内核复核 CLI（`node --import tsx scripts/e2e/routetool/validate.mjs --level <id>
  [--trace <out>]`），WIN/FAIL 退出码，trace 落逐帧位置供诊断。
- `optimize.mjs`：±1f 容忍硬化器——逐事件 ±1f 扫描 fatal，坐标下降成组平移（同角色 12f 内
  相邻事件连动，单点/整 run 两档，位移 ±1..±4），候选需过局部 ±1 验证；每轮净恶化回滚历史最优，
  最优快照随时落盘（`<route>.best.json`）；默认写 `<route>.opt.json` 人工比对，`--write` 才覆写。
- 等价性取证：TS 直载内核 vs TEMP 期编译产物内核，同 v35 路线前 700 帧逐帧位级比对 0 分歧
  （TEMP/routetool-check/，校验后该目录已清理）。

**真实门禁链**（`scripts/e2e/route.mjs`，0 钩子）：
- 时基锚定用**服务端 `[phase] ready/started @wall` 日志**（335b5e7 加的纯观测戳）——旧锚
  （页面 ready 观察 +2000ms）把客户端 ~50ms 观察延迟系统性算进零点，被 tick 取整成混合 +3f/+4f 滑帧。
- mono↔wall 桥接：`EPOCH = performance.now() - Date.now()` 在锚定后现算，补齐 T0 到观察点间的墙钟差。
- 服务端**输入队列按意图跨度排水**：消息带到达墙钟戳，每步 `deadline = startedWall + stepIndex*STEP_MS + 4`
  消费到期消息——彻底解耦 Windows setInterval 唤醒抖动（实测 setInterval(4) 均值 16.8ms）与唤醒相位 φ；
  110/111 逐事件精确落内核帧（1 例 +25ms 服务端管线打嗝落在容忍事件上不可见）。
- 66ms RESEND keepalive 与变化消息在消费日志中可区分（前者是同状态重发，非输入延迟）。
