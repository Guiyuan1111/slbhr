## 56.1 量具：`perf-mem-residency.mjs`

双页真实开局（`forest_bonus_2`），`--enable-precise-memory-info`（perf-client
r3 同款）逐秒采样 150s（预热 30s 不计斜率），每 10s 注入 1s 移动输入防「全静
死房」假设失真。同场快照确定性计数：纹理键数 + 源像素面积和、`BaseCache
getKeys()` 音频键数、房间实体数。

**原始回归斜率不可用作泄漏判据**：JS 堆是 GC 锯齿，斜率的符号由「加载期
垃圾何时排空」决定（本轮两场会话均测得 −750~−780 KB/分钟 = 堆在缩小）。
正确的判据是 **GC 地板线**——按 30s 桶取堆最低点（逼近真实常驻），地板
上升才叫泄漏。

## 56.2 地板线分析（主判据）

五个 30s 桶的堆地板：**26.8 / 26.3 / 26.6 / 26.2 / 27.0 MB**——
地板斜率 **+0.1 MB/分钟**，全窗地板 26.2、最高地板 27.0。
**平坦：150s 会话内零泄漏迹象。**（更长的慢泄漏若存在，其速率需 >锯齿
幅度 ~1 MB 才可能被本窗漏检；结合纹理/音频/实体三组恒定计数，会话内
无新增分配源，结构性排除。）

## 56.3 缓存确定性计数（两场会话一致）

| 项 | 值 | 漂移 |
|---|---|---|
| 纹理键数 | 20 | 无 |
| 纹理源像素和 | 24.6 MP | 无 |
| 音频键数（BaseCache） | 26 | 无 |
| platforms / props | 47 / 35 | 无 |

启动后 150s 内零缓存增长——baked 纹理（r49）、音频解码、房间实体在
started 期全部只读。结合 r52 已证的声实例上界（池 ≤ 峰值并发 2），
**会话内存的四个分配源全部实测有界且恒定**。

## 56.4 裁决：判不立项

- 堆常驻 ~27 MB、地板平坦、四缓存恒定——**没有可回收项，也没有增长项**。
- 27 MB 的绝对量级对桌面浏览器目标部署无压力；GPU 侧纹理 24.6 MP
  （≈ 98 MB VRAM 等价）由关卡分辨率决定，属保真参数非优化对象。
- 遗留说明：跨换关链的累积驻留（连打 N 关后的地板）不在本轮口径内——
  r46 已证换关走 GameScene 重建路径（`platformSounds` 等字段随实例重建，
  r52 已论证无跨场景泄漏），若未来出现「连打变卡」的实玩反馈，量具现成，
  加换关驱动即可复测。

## 56.5 量具坑（本轮新记录）

1. **`window.__fw` 即 Phaser.Game 实例**（`main.ts:726`），没有 `.game` 子柄；
   房间在 `scene.d.net.room`。
2. **音频缓存计数用 `BaseCache.getKeys()`**（`cache.audio.keys` 不是可靠
   公开面）。
3. **GC 锯齿下的泄漏判据必须用地板线**，原始斜率符号由排空节奏决定，
   两场会话都测出「负斜率」——拿它当趋势就是误读。
