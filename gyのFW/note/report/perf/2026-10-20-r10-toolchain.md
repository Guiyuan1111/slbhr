## 三、实施与判负

### 件1 vitest pool:threads（-12%）

vitest 3 缺省 forks：5 个测试文件各起进程、各自重复导入 shared 内核 + box2d vendor
（collect 1.74s）。threads 池共享进程：**3557→3110ms（-12%）**，89/89 全绿。
`--no-isolate` 实测无增益（3.14-3.20s）且弱化隔离——不用。纯 JS 内核套件无原生
崩溃面，worker_threads 语义安全。

### 件2 build/dev:client 直呼 node 脚本（build -6.8%）

package.json `build: "npm run sync-assets && vite build"` 的 npm→npm 嵌套层每跑
~330ms 纯包装开销。改 `"node scripts/sync-assets.mjs && vite build"`：
**5491→5118ms（-6.8%/-373ms）**，dev:client 同款改。**dist 产物 md5 前后逐字节一致**
（`616dd9ce289aed9bf2681617ed4ed981`）。

### 判负件A sync-assets 增量清单（回滚）

假设"全量 rm+cp 8.3MB/108 文件是 432ms 大头"被剖析翻案：裸 `node scripts/sync-assets.mjs`
全量仅 **0.10s**（页缓存热）——432ms 的 ~330ms 是 npm run 层。清单跳过只省 ~10ms，
不值 60 行复杂度 → **实施后回滚，脚本零 diff**，证据入库（r10-before/after 快照与
本节）。注：真正吃掉包装层的是件2（直呼 node），与清单互斥面的正解。

### 判负件B vite reportCompressedSize:false

实测 5.38-5.63s vs 基线 5.44-5.52s——带内无增益（dist js 块仅 3 个，gzip 报表非
瓶颈）。不做。

## 四、勘误与口径

### 4.1 sync-assets 432ms 归因勘误

首版量具把 npm test/sync 分开计时，sync 432ms 被当成拷贝成本——裸 node 直测翻案
（0.10s 全量）。教训：**npm run 层开销 ~330ms/次会污染一切"短命令"计时**，凡
<500ms 的命令计时必须裸 node 对照。件2 正是从此勘误导出。

### 4.2 npm test -9.5% vs -12% 两口径

after 快照的 npm test 含并行会话新增的外来测试文件（95 测试 vs 基线 89），-9.5% 为
混入口径；排除外来文件的配对（3.09-3.13s vs 3.48-3.65s）= **-12%** 为真实口径。

### 4.3 外来在飞文件扰动

本会话期间并行会话产生 `templeTreeBake.ts/.test.ts`（交接"在飞"滤镜槽工作）：
vitest 4 失败全部来自外来文件自身 WIP（我的 89 全绿）；typecheck 3 错同源（基线与
after 同担，配对有效）。外来文件与本轮零接触、不入本轮 commit。
