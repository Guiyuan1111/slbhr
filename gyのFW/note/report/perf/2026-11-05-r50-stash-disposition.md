## 待处置物是什么

`git stash@{0}`（drop 前 ref `3eeeec7`）里是 r45 §5.1 的
`packages/shared/src/kernel/build.ts` 改动：`groundFixture` / `quadFixture`
的顶点由「每次 `new B.b2Vec2(...)`」改成模块级 scratch 数组 + `SetXY` 直写
（并补 `|| 0` 归一 `-0`）。

r45 报告判定「带内 +0.68%（噪声 7.94%），**已回退**」，但工作区从未真正清掉，
一直以未提交状态挂着，直到 r49 收尾被 `git stash` 隔离。

## r50 复核做了什么

按「子 agent 自述成功不可作为完成依据」的纪律，本条结论由主 agent 亲自跑命令得出，
另派子 agent 独立复核（两者数字见下）。

### 1. 位级安全性：通过，且比 r45 的门禁更强

| 门禁 | 结果 |
|---|---|
| `perf-determinism --compare r44-full`（241 关，idle + scripted + switched） | **241/241 位级一致** |
| 独立的 shape-bit 哈希（50931 个 polygon，顶点/法线/质心 f64 原始字节） | 两臂 **SHA256 完全相同** |

`-0` 陷阱是真的：vendor `b2Vec2` 构造器是 `(this.x = a || 0)`（`-0`→`+0`），
而 `SetXY` 直写保留 `-0`。裸 `SetXY` 在退化/非退化多边形上都产生位差；
补 `|| 0` 后逐位相同。**这条归一化是必需的，不是可选装饰。**

### 2. 性能：r45 的「带内 +0.68%」是**测量力不足**，不是真相

子 agent 做了 5 组配对会话（共 40 对，31 轮/进程），用 md5 断言每轮跑的是哪一臂：

| 会话 | Δ | S 更快 |
|---|---:|---:|
| r49ab（7 轮/进程） | −1.18% | 5/8 |
| r49ab2（15） | −0.23% | 4/10 |
| r49ab3（31） | −1.46% | 9/12 |
| r49ab4（31） | −1.15% | 9/14 |
| r49ab5（31） | −1.70% | 12/14 |

三组 31 轮会话合并（n=40）：**Δ = −1.43%，配对 meanΔ = −4.69ms，sd = 9.21，
t = −3.22，CI95 = [−7.63, −1.75]，符号检验 p = 0.0022。**
空对照（两臂跑同一份 HEAD 代码，n=14）：Δ = +0.14%，t = 0.90，CI 含 0 → 量具无偏。

**结论：241 关聚合口径下，这个改动确实有 −1.4% 的真实效果，r45 当年测不出来是因为
单次 8 轮的臂内散布（~80ms）远大于 4.7ms 的信号。**

### 3. 但生产工作单元是**单关**，那里不可测

`World.reset(level)`（`packages/shared/src/kernel/world.ts:705`，调用方
`ForestRoom.ts:238,415`）**每次只构建一关**。主 agent 亲自复跑单关口径
（`perf-build.mjs`，`BUILD_LEVELS=forest_bonus_3`，最重关 357 poly，40 轮）：

| 臂 | 中位 | 区间 | 散布 |
|---|---:|---|---:|
| scratch | 2.32 ms | [1.52–11.29] | 9.77 ms |
| 原版 | 2.67 ms | [1.67–11.66] | 9.99 ms |

两臂散布都在 10ms 量级，中位差 0.35ms —— **完全不可辨**。

按 241 关聚合的 −4.69ms 摊到单关是 **0.019ms/关**，而单关构建本身 1.5–2.7ms、
单轮散布 0.6–16ms。**收益比噪声小两个数量级。**

## 处置结论：**丢弃**（`git stash drop` 已执行，ref `3eeeec7`）

理由（按权重排序）：

1. **真实工作单元下收益不可测**：单关 0.019ms，比单轮散布小两个数量级。
2. **复杂度与风险不成比例**：
   - 模块级可变状态（`groundScratchVerts` / `quadScratch`）跨所有关/所有 body 共享；
   - `|| 0` 归一化是**必需**的脆弱前提（不写就位差），未来任何新增调用点都可能踩；
   - `GROUND_SCRATCH_MAX = 8` 是对 `SHAPE_PTS` 的无断言耦合，出现 9 点模板会崩在
     `groundScratchVerts[i].SetXY` 的 `undefined` 上；
   - 只消掉约 6% 的 `b2Vec2` 分配，而 r45 报告误把它算作「消掉 `b2PolygonShape`」——
     **每 fixture 仍分配一个 shape**，报告描述与代码不符。
3. **r45 的数字虽错、结论仍对**：报告写「+0.68% 带内」，真实是 −1.4%（p=0.0022）。
   但 −1.4% 只是 241 关聚合的假象，按单关工作单元重算后仍判负。

## 入库的勘误（避免误导后续会话）

- r45 §5.1 的「Δ +0.68%，噪声 7.94% → 带内」是**测量力不足**，不是「效果为零」。
  真相是 241 关聚合 −1.43%（95% CI 排除 0）。
- r45 §5.1 的「把 `new b2PolygonShape()` + 4 个 `new b2Vec2` 换成…」**描述有误**：
  该改动只消除 `b2Vec2`，`b2PolygonShape` 仍每 fixture 一个。
- **判定口径**：衡量构建期改动用哪件量具，取决于**生产的工作单元**。241 关全量是
  基准口径（适合发现方向），但**判定必须回到单关**（真实调用粒度）。r45 用全量口径
  得出的「带内」与 r50 用全量口径得出的「−1.4%」都是同一个偏差的两面：**口径选错
  会让一个真实但无用的效果看起来像可优化项**。
