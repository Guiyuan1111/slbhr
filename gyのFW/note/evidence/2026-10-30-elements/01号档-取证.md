## §2 cover 语义（最高优先，已闭环）

**分布**：47 处（自有 46 + tutorials/tutorial_fire 1）：crystal 23、light 9、fire 7(+1)、forest 3、ice 2、water 2、wind 0。
对象形状完全一致：`{name:"", type:"cover", x, y, width, height, rotation:0, visible:true}`——**无 properties、无 gid、无形状**（实测例 Portals_2.json id121：x−8 y−8 w112 h296）。

**bundle 反解**（3 处语义锚，其余 12 个 'cover' 命中全是菜单滑条 UI，与关卡对象无关）：

1. 机关分发表 @1840569：`cover: Devices.BackgroundCover`（与 platform/portal/slider/window 同表）。
2. 类定义 `define("States/Level/Devices/BackgroundCover",["Phaser"])` @1617424–1618847，**继承 Phaser.Group（不是 Device 基类）**：
   - 构造：`sprite = make.sprite(x, y, "MechAssets", "BackgroundCover0000")`，拉伸到对象 (x,y,w,h)，`layers.background.addChild(e)`。
   - `ocupy(grid)`：把矩形覆盖的 Ground 图层瓦片（x/32…x/32+w/32+0.5，y 同理）逐个标 `tile.ocupied=true`；`ocupyTile` 越界安全。
   - **无 update / 无 updateState / 无 body / 无 lights**——静态，零每帧行为。
3. 调用点唯一：Level 世界构建 `decorate(devices)` @1798408：`null != v.ocupy && v.ocupy(s.layers[o].data)`（o=0 即 Ground 层数据）。decor 随机撒草/石子的循环里 `!t(i,h).ocupied` 才放置。

**图层栈**（setupLayers @1903210，自底向上）：`background → tutorial → underGround → lights → ground → overGround → chars → overChars → decorations → liquids`（另有 ui/dust）。background 层同时承载整关的 `TempleAssets/BackGround0000` 石纹平铺（applyFilter @1801790）。

**纹理**：`MechAssets.json` 唯一 Cover 帧 `BackgroundCover0000` = **32×32 纯黑 (0,0,0,255)**（逐像素实测）。

**判定**：cover = **纯视觉遮罩**——在背景层铺一块可伸缩黑矩形（把石纹背景"涂黑"，用于无地形的空洞/墙体内部），附带**抑制装饰撒布**（ocupy 仅服务 decor 生成，影响的是草叶/石子这些随机点缀，不是物理）。
**不挡光束、不挡风、不碰撞、不隐藏角色**。mech 分发表虽登记它，但 BackgroundCover 不继承 Device、无 registerDevice，MechManager 状态机不跟踪。
**复刻口径**：服务端 level2 解析直接忽略（无碰撞体）；客户端可选实现：黑矩形铺在 ground 之下 + decor 撒布跳过该矩形。若不实现客户端部分，仅损失"原版里被涂黑的区域有石纹背景"这一观感差异，玩法零影响。

## §3 multi 选关结构（七个子树还是一张图？——横向条带 + 每庙一张 rows 小图）

- **temples 数组消费** @2197104（Progress.fetch）：`[].concat(gameConfig.temples)` → 逐条 `$.ajax("./data/"+id+"/temple.json")` 并行取 7 份合成 `{temples:[...]}`；`myKeys = gameConfig.defaultKeys || []`（unlock_key 白名单；E 全 `unlock_key:"free"` → 恒解锁，defaultKeys 恒 []）。
  存档按 temple.id + level.id 回填 best/played/attempts。
- **type:"multi" 分叉** @2213529：menu state 挂 **TempleSelectorHybrid**（legacy 挂 SingleMenu/TempleHall）；设置按钮帧组不同 @1977644。
- **顶部条带**（TempleSelectorHybrid @1953xxx）：`icon_distance = 256*0.7`；**图标 x = temple.index × icon_distance** → 七庙在同一条横带上按 index 排开：ice(−3) wind(−2) water(−1) forest(0) fire(1) light(2) crystal(3)，由 forest 向两侧展开。图标帧 `TempleIcons` 图集 `<id>Icon0000/0001/0002`（7×3+default 共 22 帧，实测）；locked→金锁+购买弹窗；softLocked→SoftLockMenu 弹窗。背景 = 当前庙的 `TempleHall<Cap>.jpg`（locked/soft 为黑底）。
- **进庙后**（LevelMenu @1943783 / 1936177 两变体）：`"tree"===type ? LevelMenuTree : LevelMenuGrid`——**rows 走 Grid**。两者仅按钮尺寸档不同（grid 0.45–0.55 / tree 0.5–0.6），布局共用 **LevelMenuButtons** @1919015：
  - 行高 `o=min(0.6·h,700)`，列距 `M=2o/√3`（三角格）；`X=(B+x−minx)·M, Y=(C+y−miny)·o`（x/y 归一化坐标→像素）。
  - edges 非空才画连线（E 恒空 → 无连线，纯点位排布）；底板帧按 level.type：`Diamond[_Puzzle/_Speed/_Dark]_Bkg_Mask0000`；temple.color 做 bevel/outline 染色；state 0/1→"0000"、2→"0001"、3→"0002"、4→"0003"。
  - 进关按钮帧 `<type><suffix>`；`NewSign0000` 新关标 / `Lock0000` 锁。
- **rows 的解锁状态机**（Progress.setStates @2199520 的非 tree 分支）：
  `state = best.stars==3?4 :2?3 :1?2 : (allIsLearned(level, id===0) && !locked && temple.completedCount>=level.required ? 1 : 0)`。
- **元素学习门**（allIsLearned @2200263）：level.elements 缺省=true；**id===0（教学关）时元素表 slice(0,-1)**——去掉最后一个（=本关要教的新元素），只要求前置元素已学会。`learnedElements` = 所有通关关 elements 的并集。
