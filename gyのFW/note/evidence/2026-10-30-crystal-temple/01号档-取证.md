## 1. Portal 语义（五问逐答）

### 1.1 定义与默认属性（问题①的"构造参数与默认 properties"）

- 模块：`define("States/Level/Devices/Portal", ["./BoxedDevice"], ...)` **@1683669**。继承 BoxedDevice（其构造把对象锚从"左下角"换算到体中心：`c.x += mpx(boxSize.x/2)`（rot0 时 +32px）、`c.y -= mpx(boxSize.y/2)`（-48px），BoxedDevice 定义 **@1623550** 起）。
- 类默认（prototype.options）**@1690356**：`{ sensorWidth: 2, sensorHeigh: 1.5, lightSensorWidth: 0.1 }`（米；拗口原样）；`boxSize = {x:2, y:3}` → 与图块 64×96px 吻合（32px = 1m）。
- **tileset 默认属性**（`assets/tilemaps/tilesets/LargeObjects.json`，D 与 A/B/C 逐字节同库）：
  - localId 0：`{group:0, inverted:false, portalId:0}`
  - localId 1：`{group:0, inverted:true,  portalId:0}`
  - localId 2：`{group:0, length:10}`（wind，非本档对象）
- **属性合并链（三级，实测验证）**：
  1. 关卡加载器把每 gid 的 `{type: tiles[localId].type, properties: tileproperties[localId]}` 建成映射 `r`，对 Objects/Chars 层每个带 gid 对象 `_.deepObjectExtend(obj, r[gid])`（**@1893230** 起：`(g[+f.firstgid + +a] = { type: f.tiles[a].type, properties: c })`，`o(q.objects.Objects)`、`o(q.objects.Chars)`）。对象显式属性优先，缺省由 tileproperties 补。
  2. Device 基类构造 `_defaults ← 关卡对象 ← 类 options` 三段 deepObjectExtend **@1618892-1619017**。
  3. 运行时补刀：connectPortals 里 `properties.inverted || (properties.inverted = !1)` **@1835985 邻域**。
  - 实机验证（probe devices dump）：crystal_04 id66 关卡里只写了 `{initialState:1}`，运行时 options.properties = `{initialState:1, group:0, inverted:false, portalId:0}` —— 三个缺省全部补齐。
  - 注意：Phaser TilemapParser 拷贝对象时**丢弃 `id` 字段**（只留 gid/name/type/x/y/visible/properties **@1039280 邻域**），故运行时设备无 id 可用；`options.type` 即机关类型字串，`MechManager.classNames` 按 type→类映射（**@1838395**：`portal: Devices.Portal` 等 19 类，含 `cover/window/roman`）。

### 1.2 成对/成组规则（问题②）

两条正交通道，代码级无歧义：

- **配对 = `portalId`**。`MechManager.connectPortals()` **@1835885**：
  ```
  j = {};  // portalId -> [portals]
  按 deviceGroups 遍历，凡 options.type==='portal'：j[properties.portalId].push(c)
  对每个 bucket：i[0].other = i[1]; i[1].other = i[0]; 双方 inverted 缺省补 false;
  connectToWall(i[0]); connectToWall(i[1]);
  ```
  - **与 group 无关**；level 数据保证每个 portalId 恰好 2 个（无 portalId 的对象补默认 0 后参与同 bucket）。
  - 普查（本槽脚本，gid 归属按逐关 firstgid）：**正式 35 关中 34 关有 portal（crystal_20 无 LargeObjects 引用、零 portal），共 176 实例**（=普查口径 176 ✓）；教学关 tutorials/crystal_03 另有 8 个，合计 184 = 92 对。
  - 92 对构成：**mixed（一 false 一 true）32 对、same0（双 localId0）50 对、same1（双 localId1）10 对**。逐关明细见 §5.4。
  - connectPortals 无守卫：单元素 bucket 会让 `i[1].options` 抛 TypeError；实测数据因"缺省 portalId=0 归并"恰好都成对（crystal_17 唯一显式 `portalId:0` 与无 portalId 者归并成对——这是默认合并的强证据）。
- **group = 电路**（与其它机关共用）。`MechManager.registerDevice`/`deviceChanged` **@1835305**：带 `signal` 的源（lever/pusher 等翻转发 signal.dispatch）状态 OR 后，赋给同 group 全部无 signal 接收者并 `_updateState()`。portal 是接收者：**同 group 的 lever/pusher 开关 portal**（crystal_04：pusher group2 ↔ portal 对 group2（无 initialState → 初始 state 0 常闭））。
- `initialState`：Device 基类 `this.state = +properties.initialState || 0` **@1619xxx**（切片可见）→ 1=初始开，缺省/0=初始关。

### 1.3 传送触发几何（问题③"矩形 sensor？半径？"）

portal 静态体（`body.mass=0`，`SetAngle(options.rotation)`，度→弧度在 Device 基类 `options.rotation = π*deg/180`）挂**两个 fixture**（构造 **@1686405-1687172**，filter cat/mask 均 4096 **@1686625/1687138**）：

| fixture | 形状（米） | isSensor | 用途 |
|---|---|---|---|
| `sensorFixture` | `SetAsOrientedBox(2, 1.5, 0, 0)`（即 ±2m×±1.5m，全宽 4m×3m） | true | 近身检测（nearBodies：视觉裁剪 mask + 辉光 + side 守护）；lightProperties `{type:"transparent"}` = 光束直穿 |
| `eventHorizon` | `SetAsOrientedBox(0.1, 1.5, 0, 0)`（x 向 ±0.05m 的薄片，全高 3m） | **false（实体）** | 传送触发面；lightProperties `{type:"portal", getOutput, getPoint}` |

- 4096 (0x1000) 是 portal 专用碰撞位：**只有各可传载体的"portal-sensor 标记 fixture"与这两个 fixture 相互作用**：
  - character：r=0.1 圆 @质心，cat/mask=4096，`groupIndex=-1`，userData `{"portal-sensor":true}` **@1818954-1819236**（主碰撞体 cat16/mask4353 **@1817742/1818503**，与 4096 无交集 → 角色身体不与 portal 面碰撞）。
  - Ball（**@1625817**）与 BoxPrototype（**@1636063**）：同样 r=0.1 圆标记，cat/mask=4096（box 的 userData 另带 lightProperties transparent）→ **角色、箱、球都可传**。
  - 其它机关（lever/pusher mask 61695 等）不含 4096 → 不受 portal 影响；液体（Liquid killFixture mask 4369）亦不与 4096 作用 → **液体/钻石不经 portal 传送**（钻石无标记 fixture）。
- 触发逻辑（eventHorizon 的 fixture 回调，**@1689788 邻域**）：
  ```
  begin-contact：h = body 在 portal 本地系 x；side = (h>0&&!inv)||(h<0&&inv) ? 1 : -1
  若 !body.lastTransport || now-lastTransport>200：记 lastTransport=now，
      transporting.push({body, vel: 当前线速度快照, side})
  否则 console.log("prevented transport...")（200ms 每体冷却）
  ```
- `sensorFixture` 的 nearBodies 回调（同处）：begin→`createMask`（把载体 sprite 用矩形 graphics 裁剪出"半个身子在门里"的视觉效果，mask 覆盖平面背侧 5m）并记 `nearBodies[bodyId]={body,side}`；end→移除。update 每帧检 **side violation**：载体本体系 x 符号与登记 side 相反（穿面未传）→ `SetPosition(pos + local*(-2))` 镜像弹回（**@1691425 前 update 内**）。
- Phaser box2d fixture 回调签名 `(bodyA, bodyB, fixtureA, fixtureB, isBegin, contact)`（派发 **@1607500-1607900**；`setFixtureContactCallback` 注册 **@1583371**）。

### 1.4 传送语义（问题④"出口偏移/速度/冷却/可传对象"）——`transport()` **@1691425**

```
e = (0,1).SelfRotate(this.rotation)            # 门平面方向（本地方 +y 轴）
d = bodyPos - this.pos                          # 入口相对偏移
若 other.inv !== this.inv：d = e*(2(d·e)/|e|²) - d   # 关于门平面镜像
d = d.SelfRotate(other.rot - this.rot)          # Δ 转动
SetPosition(other.pos + d)                      # 出口位置
若 other.inv === this.inv：g = vel.SelfRotate(-Δ) 再关于 e 镜像
否则：                    g = vel.SelfRotate(Δ)      # 只转不镜
若 |g| < 10：g = normalize(g) * (10/bodyMass)   # 最低出口速率
SetLinearVelocity(g); game.physics.update()     # ★同步嵌套推进一步物理
sounds.portalTransport.play(); sensorFixture/eventHorizon.Refilter()
```

**逐条回答**：
- **出口偏移**：入点相对偏移保留（混合对镜像到出口门另一侧；同 inverted 对同侧穿出），再叠加两门 rotation 差。
- **速度**：混合对（inverted 不同）= 旋转 Δ，方向不变直穿；同 inverted 对 = 旋转 -Δ 后镜像 → 实测即"关于出口门平面镜像"（Δ=0 时 vx 反号，向回弹，见 §5 case2）。
- **最低速率**：|g|<10 → `normalize(g) × (10/mass)`。注意 10 除以的是**质量**（角色实测 mass=0.9548 → 10.4734 m/s；重箱会更慢）——原版把冲量当速度用的老毛病，原样复刻。
- **冷却/防回传**：两层——(a) 200ms 墙钟 per-body 冷却（`lastTransport`）；(b) 传送内嵌 `physics.update()` 一步 + Refilter。另注意 marker 与 eventHorizon 都是实体 → 载体是被"贴面即传"的，正常情况不会物理穿面；**若出口点仍压着出口门平面，同一物理步内可能连环再传（乒乓），200ms 冷却把频率限到 5Hz，靠重力/位移自然脱出**。same-inverted 对的出口速度本来就朝门回弹，实测实验室里连环触发（7486 次/约 4 分钟墙钟）——**这是原版固有行为，必须复刻，不要"修"**。
- **可传对象**：凡带 portal-sensor 标记者 = 角色 fb/wg、Box/BoxHeavy、Ball。钻石/液体/其它机关无标记不传。
- 死代码备忘：`transport` 里 `f = other.normal.Clone(); if(side===1) f.SelfMul(-1)` 算出的 f **从未使用**（原版遗留），最低速率方向实际= 归一化出口速度。
- 每帧 flush：`update()` 把 `transporting` 队列逐个 transport 后置 null；`receiving` 标记防同帧互踩。

**探针对拍（oracle 实机，§5.2 完整表）**：混合对 offset 镜像/速度直穿、同 inverted 对 offset 不镜像/速度镜像、10/mass 地板、rot±90° 的 CCW 旋转方向——全部与上式吻合（误差 ≤ 一步嵌套积分 0.0087·|v| + 求解器推出量）。

### 1.5 与光学系统（rotmirror/beamer）的交互（问题⑤"光束能否过 portal"）

**能，且是 first-class 语义**。Beamer 射线回调（**@1629893-1630392**）按 fixture 的 lightProperties 分派：

- `transparent` → 直穿（portal 的大 sensor 区即此类型，光束贴着门面通过不被截）。
- `portal` 且 `device.state===1`（开）→ `{ point: getPoint(命中点,法线), output: getOutput, skipPoint: 命中点 }`：画线到入口命中点（skipPoint），跳到**出口门上的映射点**继续，方向取 `getOutput(入射方向)`；一次射线最多 **12 段**（`j.length < 12`）。
- portal 关（state 0）→ fixtures 已被 `SetFilterData({mask/category:0})` 禁用 → 光不交互（直穿）。
- `getOutput` **@1687274**：`dir.SelfRotate(other.rot - this.rot + (invSame ? π : 0))`。
- `getPoint` **@1687675**：点先（inv 不同才）关于门轴镜像，再旋 Δ，加 other 位置。
- ⚠ **存疑待核（如实记录，不下终判）**：同 inverted 时，光的 `getOutput` = `R(Δ+π)`，而实体 `transport` = `R(-Δ)+镜像`（Δ=0 时即镜 x）。对 rot0 竖直门面，二者对一般向量**不等价**（vy 符号不同：`(-vx,-vy)` vs `(-vx,vy)`）——即光与实体穿过同一对门时出口方向变换在原版里就**不一致**。6.3 槽实现时建议照抄两套公式（光一套、实体一套），不要"统一"。

### 1.6 状态机 / 假墙 / 音效（补充语义）

- `updateState` **@1692242 邻域**：state1=开（center 可见、两 fixture filter=4096、portalOpen 音 + portalLoop 循环 volume 0.3，辉光随近体距离升到 1）；state0=关（center 隐藏、filter=0、停 loop、portalClose 音）。`resetStates` 调 `updateState(true)` 静默重置。

- `drawDarkMask`（**@1682254**）：dark 型关卡（light 部专属，crystal 无）里门户两点 ±36px 的径向辉光。
- 音效四键 `["portalOpen","portalLoop","portalClose","portalTransport"]` **@1690517**；装载映射 `key → assets/audio/首字母大写.mp3`（**@1889882**：portalOpen→PortalOpen.mp3 等，四文件 D/C 同库）。

## 7. 风险与未决项

1. **乒乓行为**（same-inverted 对出口速度回射）：原版固有，须原样复刻；若我方加"防回传"会破坏依赖它的关卡节奏（如 crystal_26 same0×3）。
2. **嵌套 physics.update**：transport 内同步推进一步物理，等效于传送当帧多积分一步 + 接触求解器推出。内核若在固定步长外层做传送，需补一步 settle 才能对拍。
3. **200ms 墙钟冷却**：与帧率无关（Date.now），speed 型关卡回环路线要留 ≥12 帧。
4. **light 与实体的同 inverted 变换不一致**（§1.5 ⚠）：建议两套公式照抄，勿统一；待 5.3 若有光穿门路线再做实机对拍。
5. **connectPortals 无守卫**：我方实现建议按"portalId 恰好 2 个"的现数据契约做，但对缺省 portalId=0 的归并必须保留（crystal_17 依赖）。
6. crystal_20 无 portal/wind（无 LargeObjects 引用）——数据管道不得假设 tilesets 恒含 4 项。
7. 教学关 crystal_03 的 8 个 portal 走 tutorials 目录共享文件，落库时注意路径去重。
8. 本档未做：box/ball 载体的实机传送对拍（marker fixture 代码证据完备 @1636063/1625817，行为与角色同路径）；如 5.3 需要，可复用 tools 探针加 case。
