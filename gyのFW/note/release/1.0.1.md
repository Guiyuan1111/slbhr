# 1.0.1——分发包「开局必崩」根治 + 真开局验收门禁

修复 1.0.0 分发包的致命缺陷：**六步验收全绿，玩家一建房就永久卡 loading**。同时把分发线合入 main 的 0.3.56–0.3.58 全部修复（1.0.0 从 0.3.55 分出后未再跟进）。

完整事故复盘见 [../issues-2026-10-20/51-deploy-startup-crash.md](../issues-2026-10-20/51-deploy-startup-crash.md)。

## 根因（三层叠加）

1. **编译链**：包发 TS 源码 + `node --import tsx` 启动。tsx 4.23.15 的 `useDefineForClassFields` 归一化只存在于 CJS require 钩子，**ESM loader 完全不读**；包内又恰好缺 tsconfig。于是 `x!: number` 被编成原生 class field，覆盖 Colyseus schema 在实例上装的访问器 → 变更不进 ChangeTree → 首次增量广播 `encodeValue` 读 `Symbol.metadata` 崩 → 整进程带崩。
2. **客户端 P0**：0.3.56 才修的 seedrandom `new Function`（CSP 禁 eval）——即便服务端不崩，浏览器也进不去 Game。分发线缺此提交。
3. **验收盲区**：§5 第 ⑥ 步只 `create→leave`，房间状态从未广播增量，崩溃路径完全未被触及。

## 修复

**语言层（根治）**：`state.ts` 全部 64 字段改 `declare` —— 纯类型标注，任何转译器都不产运行时字段，不再依赖 tsconfig 是否随包。

**运行层**：`package-deploy.mjs` 改为构建期 esbuild **逐文件预转译**（不打包：`import.meta.url` 的 ROOT/vendor/TEMP 锚点天然正确）。目标机直跑 `node packages/server/src/index.js`，**不需要 tsx 或任何构建工具**；包内不留 TS 源码。

**启动层**：新增 `schemaSelfCheck.ts`，监听端口前逐类逐字段校验描述符必须是访问器，形态不对立即退出——把「建房十秒后崩」提前到启动第一秒。启动首行日志即 `[fw] schema 自检通过（10 类字段访问器完好）`。

**验收层**：DEPLOY §5 第 ⑥ 步改为双人进 `started` + 断言 patch 持续增长（实测 59.4/s）。

**门禁层**：新增 `scripts/e2e/deploy-smoke.mjs`（起服→双人开局→patch 持续→进程存活→浏览器进 Game 且 pageerror=0），三处复用：打包链内部、release-asset CI（解包到独立 tmp 目录后）、ci.yml 源码树作业。

## 附带修复

**加载条填充条错位**：oracle `LoaderBar` 是 Phaser2 `Sprite`（anchor 缺省 `0,0`），我方 Phaser3 `Image` 缺省中心锚，而 `setCrop` 恒自左上起裁 → 填充条左移 100px、上移 10px 甩出金框。修法 `setOrigin(0, 0)`。
