# 0.3.27 — 门扫帧 round 闸门卡摆修复：真实游玩通关链全线打通

用户实测「双人都站进各自门内仍无法进入下一关」的全流程排查结案。并发双代理（服务端→客户端全链路审计 + 原版 bundle 字证）+ 内核逐帧探针定位根因；成因与取证全档 `note/research/2026-10-fidelity/13-door-sweep-stall.md`。

## 根因修复

- **门扫帧状态机卡摆**（kernel `updateDoors`）：推进闸门 `round(frac) < 21` 使 frac 恒卡 **20.83 帧**（差 0.17 帧不到 21），`isUp` 退化为「signaled 单步脉冲」——双门错峰到齐时两脉冲几乎不可能同帧重叠 → `checkEnd` 永不 win；客户端 `doorFrame` 恒 20 → 门动画永远差一帧不全开。修复：闸门改用 frac 本身（可达 21 并钳制），`isUp` 改原版口径每步重算（站门持续为真、离开随扫帧回退）。历史测试全绿的原因：传送实验与 `FW_DEBUG_FORCE_DOORS` 均为双门锁步同帧到位，恰好绕开错峰路径。
- **原版语义字证**：通关唯一判据 `door1.isUp && door2.isUp`（@1950848），无钻石/时长/站位前提；`isUp` 每帧由精灵帧重算、signal 每帧驱动 `checkEndGame`（@1682906）；教程纯显示不 gate 门（@1937443）。

## 回归加固（防复发）

- 内核单测「双门异时到位」：先到者 `isUp` 首真后连续不掉、后到者 1.33s 后补齐 → win；已验证对旧实现精确变红。84/84。
- e2e 新增**真实走位入门通关**模式：探针关 `zz_probe`（forest_01 克隆、出生点在门带左侧）固化为 fixture（运行时安装/自动移除），真实服务端 + 双浏览器回放键盘时间线，断言 HUD「通关！」——真实接触→开门→win→phase→客户端全链在体验证，不再依赖 `FW_DEBUG_FORCE_DOORS`。

## 附带修复（链路审计副产物）

- `BodyState.state` 漏注册 defineTypes——0.3.25 平台灯罩换帧从未真正下发，本版起生效。
- `setPaused` 先置位后 emit 被闸拦——暂停瞬间末次按住态留在服务端致角色持续怼墙；改为置位前发「全松」快照。
- 自动重连丢弃新 Room 实例——重连后全部回调静默失效；重构 `bindRoom` 换绑重挂。
- 断线 60s 超时后 phase 永久卡 paused 成死房——仍有一人在场时回 lobby，补位 join 走 `restartLevel` 整关重开（原版 retry 语义）。
