# 1.0.2 — 一键部署闭环

> 发布日期：2026-10-28 ｜ 上一版 1.0.1

## 一句话

把包丢给任何 AI，跑 `sudo ./deploy.sh` 即完成部署并自证可用；同时把打包链改成三部分发共用一套脚本（1.x/2.x/3.x）。

## 玩家/运维可见

- **包内自带一键部署入口** `deploy.sh`：校验环境（root/Linux x64/Node ≥22.12/端口空闲）→ 生成 systemd unit（路径自动填，不用手改）→ 起服 → 跑 9 项验收，全绿退出码 0。
- **包内自带验收脚本** `verify.mjs`：`/healthz`、首页、关卡清单与包内实装逐一致、本部首关 200 与别部关 404、音频流、建房、双人到齐进 started、started 期 patch 持续在流、浏览器建房进 Game。
- 服务名、监听端口缺省、本部首关、成员边界全部由包内 `data/` 自动认定——forest/light/ice 三种包共用同一份脚本，不会串部。
- 修 1.0.1 的一处验收假阳性：③ 原按 `forest_` 前缀判断，对 light/ice 包会误报（这两部的关卡清单合法交叉引用别部教学关）。

## 工程

- `package-deploy.mjs` 参数化：`--temple forest|light|ice`。剪裁集**由该部 temple.json 清单推导**（清单引用到的关卡文件全保留，含 tutorials 交叉引用），不再按文件名硬编码；新增 `--plan` 只打印打包计划。
- 新增 `scripts/first-level.mjs`：本部首关推导的唯一实现（处理「首关在 tutorials 下」「ice 清单 initial 指向别部关」两个陷阱），打包器 / 验收脚本 / CI 三处复用。
- `release-asset.yml`：tag 守卫从 `1.0.*` 扩为 `1.* / 2.* / 3.*`，主线号→分部映射写死在 Guard 内，不符即拒；解包复验新增「别部数据目录不得残留」断言。
- 新增 `drift-check.yml`：每周检查各 `release/*` 相对 main 的落后量与闲置天数（阈值 20 提交 / 7 天），超阈值标 DRIFT 并写 job summary——补 1.0.0 事故里「分发线安静腐烂」那一段流程缺口。

## 实测

- forest 包（48 关）：打包 → 真开局冒烟 → 包内自验收，全绿。
- light 包（41 关）：**同一套脚本**全绿；干净目录 `./deploy.sh --no-service` 一条命令部署，9 项验收全绿；包内确认无别部 `data/`、无别部图集、无 `.ts`、无 `__tests__`。
- `--plan` 对三部输出正确（forest 48 / light 41 / ice 53 关，教学关保留集各自正确）。
