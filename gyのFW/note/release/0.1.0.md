# v0.1.0（M1 里程碑：可玩的联机最小闭环）

> 注：史前批次（monorepo 迁移前），无对应 git tag 与 GitHub Release；自 0.2.0 起才有 tag，自 0.3.48 前后起发版流程（四件套）成形，0.2.0–0.3.46 缺项已于 2026-10-27 批量补账。

**日期**：2026-09-30 · **对应计划**：[PLAN.md](../PLAN.md) 里程碑 M0-M1

## 新增

- 工程骨架：npm workspaces（shared / server / client）+ TypeScript 严格模式 + Vite + Vitest + tsx。
- 官方素材与关卡数据接入：`assets/`、`data/` 由 `scripts/sync-assets.mjs` 同步到客户端（构建时自动执行）。
- 共享内核 `@fw/shared`：调参入口 `params.ts`（重力/速度/跳跃/判定尺寸等全在这里）、Tiled 老格式关卡解析（`level.ts`）、60Hz 固定步长物理仿真（`world.ts`，含平台/拉杆/液体致死/钻石/双门通关）。
- 服务器：Colyseus 房间（密码校验、2 人、角色分配、断线冻结 60 秒 + 令牌重连）、express 同端口静态托管（构建产物 + 素材 + 关卡 JSON）。
- 客户端：Phaser 3 渲染（官方 atlas 帧 / 图块集 / 液体动画 / 门 / 钻石 / 拉杆 / 移动平台）、指数平滑插值（自己 22/s、对方 12/s）、键盘输入（方向键=火人、WASD=水女孩）、DOM 菜单与 HUD（房间码、密码、计时、钻石计数、断线提示、通关面板 + 再来一局）。
- 首关 `forest_02`：8 红 + 8 蓝钻、4 拉杆 + 2 移动平台（其余机关 M3 按 gid 枚举扩展）。

## 验证记录

- 单元测试 10/10（真实 forest_02 数据：尺寸/出生点/液体/移动/跳跃/绿浆致死/双门通关/拉杆联动）。
- 双客户端冒烟 9/9：创建 → 错密码拒绝 → 加入 → 角色互异 → 状态同步 → 输入驱动移动（dx≈440px）→ 钻石全量同步 → 断线冻结 → 自动重连恢复。
- 浏览器实测（开发模式）：双页面同房间、角色火/水互异、计时走动、HUD 计数正确、零 console 错误。

## 本版修过的坑（复用时注意）

- `colyseus` 主包（CJS）与 `@colyseus/ws-transport`（ESM 入口）会各拿一份 `@colyseus/core` 实例，表现为 "seat reservation expired"——服务器统一走 `colyseus.cjs.ts` 的 require 链。
- Schema 类字段必须写进 `constructor`（原生 class fields 会绕过 setter，编码时类型元数据缺失直接崩）。
- 官方 Tiled 老格式的外部图块集引用条目没有 `name` 字段，只能按 `source` 文件名匹配。

## 已知限制（下版处理）

- 水池/岩浆的瓦片类型（`LIQUID_TILE` 5/6）是经验推导，若试玩发现火人能趟水需对调常量。
- 插值是指数平滑（非 100ms 快照缓冲），公网高延迟下远端会略抖，M3 升级。
- 关卡单一（forest_02）；金币音效、背景音乐、触屏按键、更多机关均为后续里程碑。
