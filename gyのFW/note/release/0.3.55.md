## r21+r25：循环曲与终局时刻曲出落定门
- 动机：三族化后暖装落定门（bgWarmSettled，挡 enterGame）仍装 4 支音频——循环曲是进房段单笔最大字节（LevelMusic 1,315,960B）却没有一帧靠它；终局时刻曲（失败曲 163,438B+族终局曲）出声时点必然晚于进房数秒。
- 落定门与 GameScene.preload 阻塞批内只剩 AUDIO_SFX（18 支机关声）；BGM 全改门后二段：门落定 1500ms 后 BootScene.thenBgmDefer 取 warm 族 loop+terminal（Menu 被切走则定时器随场景作废）。
- 兜底：create 后 kickBgmLoop/kickBgmTerminal——缓存命中零请求零延后（常规路径 create 当场有声）；未命中装载完成后补起。补起三卫：stairsPlayed（终局接管不补）、bgm_over/finishKey 在播（不叠播）、本键在播。终局曲补起另加 won 相位卫：死亡失败曲是时刻绑定一次性音不补（晚到会盖住重生后的跑动），终局曲晚到仍是那句结尾。SHUTDOWN 摘 load complete——LoaderPlugin 随场景复用，防 once 累积多播。
- 门挡字节出门（对 0.3.54 口径）：general 族 1,647,015B / speed 族 343,792B / dark 族 812,753B（门内音频只剩 sfx）。qoder 弱网档同件实测 −2.1~21.4s（其 r21 报告口径）。
- 验证：audio-families.test 重写 9 例（拆分恒等 loop∪terminal=族包∪失败曲、GAME_BGM_KEYS 恰为三族并集、release 先实例后缓存序）；audiofamily.mjs 新增时序断言——__fwBgmDeferAt 与各曲 Resource Timing startTime 须晚于 __fwWarmGateDoneAt+1400ms，3/3 PASS（实测 speed 例门后 3823ms 起请求，门内零 BGM）。
